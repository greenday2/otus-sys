# Обработка сигнала SIGFPE (Rust)

Перехват `SIGFPE` в Rust на Linux x86_64 и пропуск сбойной инструкции
`div`/`idiv` с обнулением `RAX` и `RDX` в сохранённом контексте. 
(АРМ-Style поведение)

## Что делает программа

1. Устанавливает обработчик `SIGFPE` через `sigaction` с флагом `SA_SIGINFO`.
2. Выполняет деление через inline asm (`div`), передавая делимое и делитель из аргументов.
3. Если делитель равен нулю, ядро доставляет `SIGFPE` с `si_code == 1`.
4. Обработчик:
   - извлекает `RIP` из `ucontext_t`;
   - декодирует инструкцию по адресу `RIP` с помощью `iced-x86`;
   - проверяет, что это `div`/`idiv` любой разрядности;
   - обнуляет `RAX` (частное) и `RDX` (остаток);
   - сдвигает `RIP` на длину инструкции, чтобы CPU перешагнул сбойный `div`;
   - выставляет атомарный флаг `SIGFPE_HANDLED`.
5. Основной код по флагу различает два исхода и печатает результат.

## Требования

- Linux x86_64 (раскладка `ucontext_t` и индексы `gregs` платформозависимы).
- Rust stable (inline asm стабилизирован).
- Крейты:
  - `libc` — доступ к `sigaction`, `ucontext_t`, `siginfo_t`;
  - `iced-x86` — декодирование инструкций x86 и определение их длины.


## Сборка и запуск

```bash
cargo build --release
./target/release/homework2 <делимое> <делитель>
```

Примеры:

```bash
# Обычное деление — обработчик не вызывается
$ ./homework2 100 3
quotient = 33, remainder = 1

# Деление на ноль — SIGFPE перехвачен, div пропущен
$ ./homework2 100 0
Восстановились после SIGFPE: quotient = 0, remainder = 0
```
